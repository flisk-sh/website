What is Flisk CLI?

Your app has parts: a website, an API, a database. Flisk starts all of them on your computer with one command.

  1. You write one small file per part, called service.json. It says what the part is.
  2. You run flisk up.
  3. Flisk writes the setup files and starts everything.

Flisk works on your computer only. It does not put your app on the internet. For that, keep using Helm, Argo CD or Kustomize. See Flisk next to Helm.

Files Flisk writes for you

You do not write these. You do not edit these. Change service.json and Flisk writes them again.

  • A Dockerfile for each service, built in four layers (L1 to L4)
  • Vite and TypeScript settings for React (the default) or Vue 3 frontends
  • nginx and Traefik rules, so each service gets its own local address
  • Environment files and an .npmrc that point at the local registry
  • A Tiltfile that starts everything
  • An AGENTS.md in each .autogenerated/ folder that tells AI coding tools to leave these files alone

Why teams use it

A new teammate runs flisk doctor and flisk up. They do not read a long setup page. We have not measured how much time this saves on a real team. See the example story.

What you get

One file per service

You describe a service once, in a short JSON file.

No Kubernetes

Everything runs on your computer. No cluster to set up.

Files written for you

Flisk writes the Docker and Tilt files. You do not.

Layered images

Docker images built in four layers, L1 to L4.

Finds your services

Flisk looks through your folders and finds each service.
