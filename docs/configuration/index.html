Configuration

Flisk has two JSON configuration files: a service.json per service and a project-level .flisk/project.json. These schemas help your editor; the CLI remains the runtime source of truth.

service.json

This backend manifest is valid JSON. Field notes follow the file instead of appearing as invalid JSON comments.

services/shop/api-backend/service.json
{
  "$schema": "https://flisk.sh/schema.service.json",
  "schemaVersion": 1,
  "appName": "api-backend",
  "appType": "backend",
  "stack": "shop",
  "port": 4000,
  "healthCheckPath": "/health",
  "dependsOn": []
}

appName, appType, stack, and schemaVersion are required; a backend also needs a port. Optional fields include dependsOn and healthCheckPath. See the service schema source. VS Code and other JSON editors can read the $schema hint.

.flisk/project.json

Use the project configuration schema through an editor association. In VS Code, add this to workspace .vscode/settings.json:

.vscode/settings.json
{
  "json.schemas": [
    {
      "fileMatch": ["/services/**/service.json"],
      "url": "https://flisk.sh/schema.service.json"
    },
    {
      "fileMatch": ["/.flisk/project.json"],
      "url": "https://flisk.sh/project-schema.json"
    }
  ]
}

flisk doctor checks local environment readiness and discovered service issues. flisk config verify checks whether generated project files match .flisk/project.json; it does not lint service.json or Helm values. Flisk does not validate your production chart.

Required fields

appName

The unique identifier for your service. Lowercase with hyphens.

service.json
"appName": "catalog-api"

appType

The type of service. Determines which generators run.

    {% for t in site.data.flisk.app_types %}
  • {{ t.name }} — {{ t.desc }}
    • {% endfor %}

Workers must enable nats in featuresEnabled. They have no HTTP server, so they get no Traefik route and no HTTP health check.

stack

Groups related services for selective startup and Tilt orchestration. flisk up <stack> starts one stack.

service.json
"stack": "reports"

port

The port your service listens on. Backends need one in 4000-5999 and frontends use 3000-3999. Flisk runs the service on exactly this port, and other containers reach it as http://<appName>:<port>. Backend ports are not published on localhost; reach them through Traefik at http://api.<project>.localhost/api/<name without -api>.

service.json
"port": 4410

Optional fields

framework

Which single-page-app provider generates a frontend's Vite and TypeScript config. Leave it out and you get React, so existing manifests are unchanged.

    {% for f in site.data.flisk.frontend_frameworks %}
  • {{ f.name }} — {{ f.desc }}
    • {% endfor %}
terminal
flisk resource web --type frontend --framework vue --stack shop

That writes "framework": "vue" into web/service.json. Docker, nginx, Traefik and Tilt are shared with React frontends. Needs Flisk CLI 1.3.75 or newer; older releases ignore the field and generate React config. See the Vue example, or add a framework.

featuresEnabled

Platform features to enable. Only these values are valid:

    {% for f in site.data.flisk.manifest_features %}
  • {{ f.name }} — {{ f.desc }}
    • {% endfor %}

dependsOn

Other services this service depends on. Flisk resolves boot order automatically.

service.json
"dependsOn": ["auth-emulator", "catalog-api"]

params

Non-secret environment variables for the container. Use them to point one service at another by resource name and port, so swapping a local stand-in for a managed service is a config change. Secrets belong in secrets, not here.

service.json
"params": {
  "OIDC_ISSUER": "http://api.my-project.localhost/api/auth-emulator",
  "OIDC_JWKS_URL": "http://auth-emulator:4400/.well-known/jwks.json"
}

The auth + queue + email example uses this to run an identity provider, a queue and email locally.

package.json scripts

Each service also needs a package.json next to its service.json, with npm scripts required by appType. See package.json scripts for the list.

Examples by type

Real manifests from the reference repositories are on the examples page. These show the shape of each type.

Backend service

catalog-api / service.json
{
  "appName": "catalog-api",
  "appType": "backend",
  "stack": "store",
  "port": 4300,
  "featuresEnabled": ["prisma"],
  "dependsOn": []
}

Frontend service (Vue)

storefront-web / service.json
{
  "appName": "storefront-web",
  "appType": "frontend",
  "framework": "vue",
  "stack": "store",
  "port": 3300,
  "basePath": "/storefront-web",
  "dependsOn": ["catalog-api"]
}
