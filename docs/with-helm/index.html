Flisk + Helm (they are not alternatives)

Flisk CLI starts services on your machine. Production deployment stays with Helm.

Machine:  service.json  →  flisk up  →  Docker + Tilt + Traefik *.localhost
Cluster: same image    →  Helm / Flux / Argo  →  Deployment + Service + Ingress

Flisk owns service scaffolding, local Dockerfile layering, Tilt, local proxy/Postgres, and selecting local stack subsets. Helm and your cluster tools own replicas, probes, ingress class, PVCs, node selectors, IRSA, and HPA. Keep bjw-s app-template, official or homegrown charts, Kustomize, Flux, and Argo in your production workflow.

These concepts have boundaries: appName resembles a release or controller identity; appType suggests but does not configure a cluster controller; port corresponds conceptually to a Service port; healthCheckPath may inform probes; dependsOn does not establish cluster ordering or chart hooks; Traefik *.localhost is not a production Ingress/Gateway; and local Postgres should be replaced or managed explicitly for production.

One backend, two paths
