Before you run it

Starting a local stack needs Docker and Tilt. The standalone CLI binary needs no host Node.js or Bun; installing the CLI from npm requires Node.js {{ site.data.flisk.prereq_node }}.

  • Docker installed and running
  • Tilt installed
  • Node.js {{ site.data.flisk.prereq_node }} only when installing the CLI from npm

Full local runtime: macOS, Linux, and Ubuntu in WSL2. The latest release also includes a Windows AMD64 CLI for inspection; native Windows does not support running a landscape.

Windows AMD64: inspect the CLI

The latest release includes flisk-windows-amd64.exe. Install it from PowerShell, then check the binary and its bundled files:

  1. Install Flisk:
    PowerShell
    irm https://flisk.sh/install.ps1 | iex

    Or download and inspect the script before running it:

    PowerShell
    Invoke-WebRequest https://flisk.sh/install.ps1 -OutFile install-flisk.ps1
powershell -ExecutionPolicy Bypass -File .\install-flisk.ps1
  2. Close PowerShell and open a new window so the updated PATH is loaded.
  3. Verify the CLI and packaged assets:
    PowerShell
    flisk --version
flisk runtime --check-assets
flisk doctor

    On native Windows, flisk doctor reports that landscape startup requires WSL2 Ubuntu. This is the expected support boundary.

For the full inner loop, follow the WSL2 Ubuntu setup. Windows ARM64 binaries are not published.

Coming from the old package? The CLI used to ship as @tdk-landscape/tdk-cli-core, and that package still owns the tdk command on your machine. Remove it once, then install Flisk: npm uninstall -g @tdk-landscape/tdk-cli-core && npm install -g @flisk-sh/flisk. Without that, npm stops with EEXIST: file already exists and the flisk command never lands on your PATH. The curl installer above has no such conflict: it writes flisk directly.

Simple setup

Once Flisk is installed — pick a method above — this is the whole happy path if you already have Docker running.

terminal
flisk doctor
flisk project example
cd flisk-example
flisk up

Verify installation

terminal
flisk --version
# prints the installed version, e.g. 1.3.74

Add your license (if using premium features)

Core stays free. Premium is a separate key for Verdaccio, DDD scaffolding, and Sablier idle stop. Playwright, C4, and AGENTS.md are free when generated in-repo; a key is required only to download their implementations.

Have a Premium or Enterprise key?

Export it before running flisk up. Flisk checks the key automatically on the next run.

terminal
export FLISK_LICENSE_KEY=<your-license-key>

Add that line to ~/.zshrc or ~/.bashrc if you want it to persist. Each key covers up to {{ site.data.flisk.premium_project_limit }} distinct projects, unlimited on Enterprise. If the key is missing, expired, or unreachable, Flisk keeps running with the free engine.

What actually happens when you run it

Before Tilt touches Docker, flisk checks your environment and tells you exactly what it's doing — no guessing what's happening behind the spinner.

zsh: flisk doctor && flisk up

Don't have Docker or Tilt yet?

flisk up won't just fail silently — it checks both before touching anything, and tells you precisely what's missing and how to fix it:

terminal
$ flisk up

Flisk can't start - missing prerequisites:

❌ Docker (or a compatible container runtime) is not running

💡 Suggestions:
   → Start Docker Desktop, then verify with: `docker ps`
   → Or start Colima: `colima start`
   → Or start the Docker service on Linux: `sudo systemctl start docker`
   → Setup guide: https://flisk.sh/docs/quickstart/

❌ Tilt CLI is not installed

💡 Suggestions:
   → Install Tilt: `brew install tilt` (macOS)
   → Or download from: https://docs.tilt.dev/install.html
   → Verify with: `tilt version`

Run `flisk doctor` for a full environment check.

Fix what it flags, run flisk doctor to confirm, and you're clear to boot.

Start from a working example

Use one known-good example first. Check the machine, clone the example, generate its local configuration, and start its shop stack.

terminal
flisk doctor
flisk project example
cd flisk-example
flisk project --yes
flisk up shop

Keep flisk up shop running. Use flisk networks for the example's URLs. See Examples for other templates after the first run.

Success

Your stack is now running locally. Every new teammate who clones the repo gets the same result in minutes, not weeks.

Build from scratch

After the example makes sense, create a blank project and add your first backend resource.

terminal
mkdir my-service
cd my-service
flisk project --yes
flisk resource api --type backend --stack shop   # asks you to confirm
flisk project --check
flisk up shop

Add a frontend the same way. It is React by default; pass --framework vue for Vue 3 (Flisk CLI 1.3.75 or newer):

terminal
flisk resource web --type frontend --stack shop                   # React + Vite (default)
flisk resource web --type frontend --framework vue --stack shop   # Vue 3 + Vite

Flisk validates .flisk/project.json, generates files in .flisk/.flisk-out/, and reads boot order from each resource's dependsOn list.

Manual binary download

Download the binary, its engine files and the checksums yourself. The binary looks for the flisk-cli/ folder next to it.

Windows AMD64

The latest release includes the Windows CLI and the PowerShell installer verifies its checksum. Native Windows supports CLI inspection only: use flisk --version, flisk runtime --check-assets, and flisk doctor. For flisk project and flisk up, follow the WSL2 Ubuntu setup.

PowerShell
irm https://flisk.sh/install.ps1 | iex
terminal
os=$(uname -s | tr A-Z a-z); arch=$(uname -m | sed "s/x86_64/amd64/;s/aarch64/arm64/")
base=https://github.com/flisk-sh/releases/releases/latest/download
curl -fsSL -O "$base/flisk-$os-$arch" -O "$base/flisk-cli-engine.tar.gz" -O "$base/checksums.txt"
shasum -a 256 -c --ignore-missing checksums.txt
mkdir -p ~/.local/bin/flisk-cli
install -m 755 "flisk-$os-$arch" ~/.local/bin/flisk
tar -xzf flisk-cli-engine.tar.gz -C ~/.local/bin/flisk-cli --strip-components=1

Binaries ship from flisk-sh/releases.

Try Flisk with Docker Compose

Use Docker Compose if you want to try Flisk without installing the binary on your host.

terminal
git clone https://github.com/flisk-sh/flisk-docker-compose-example.git
cd flisk-docker-compose-example
docker compose run --rm flisk flisk --version
docker compose run --rm flisk flisk project --yes
