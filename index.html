Honest answers

Hover to expand. The same answers we give in engineering reviews.

We need Kubernetes for production
Local dev doesn't need to match production. The 14 tiny services were healthy in 4.6s on a 16 GB M1 after images existed. Not a cold boot. Production stays on Helm. Claim details.
What about CI/CD?
Flisk is completely decoupled from your CI. Use it for local development and whatever you want for CI/CD. Nothing to migrate away from later.
Is {{ site.data.tdk.scale_plain }} services locally realistic?
As a boot test, yes: this generated /health fixture has {{ site.data.tdk.scale_plain }} small generated services (about 20 lines each) that all became healthy through Traefik in {{ site.data.tdk.erp_boot_seconds }} s on a clean CI runner, images built from scratch (the run). It is a scale fixture, not a real ERP product. Real services with real dependencies use more memory. Selective startup runs only what you're working on, and golden L1–L4 layers keep rebuilds near-instant. The discovery daemon regenerates only what changed. Our daily driver is a {{ site.data.tdk.demo_services }}-service stack on a {{ site.data.tdk.machine }}, and it performs superbly; the same engine runs a {{ site.data.tdk.monorepo_services }}-service monorepo every day.
Where do the savings numbers come from?
The calculator uses inputs you set. Its output is arithmetic, not savings. The starting value of five hours per week is only an editable input, not a typical measurement. We make no savings claim for your team.
